# v0.16.0 · Identidad y trazas internas

La integración conserva el estado documental de main e incorpora los 66 commits posteriores a v0.15.2 de la rama de robustez. Las correcciones de concurrencia, cola y errores anteriores ya formaban parte de main.

## Comportamiento disponible

Cada consulta recibe `x-request-id`; el evento SSE `done` incorpora `request_id` y el fallback web lo conserva. Si el pipeline termina sin resultado, el stream emite `internal_error`. El contrato añade ese campo sin retirar operaciones ni campos previos. La presentación de la interfaz no cambia.

## Piezas internas desconectadas

El colector se habilita solo al pasar explícitamente `trace` a las funciones internas; su valor por defecto es `None`. Ningún endpoint lo activa. El almacén `HistoryStore` y el adaptador `recorded_ask_stream` tampoco se instancian desde la API. Por tanto, la configuración pública no ofrece una opción para activar persistencia.

El almacén incluye migraciones transaccionales, reintento acotado de WAL, permisos POSIX 0600 para bases nuevas, paginación y feedback con copia de traza. Los comandos locales de revisión y exportación necesitan una base existente y pueden migrarla. La exportación produce borradores y no aprueba gold.

Quedan fuera de activación los endpoints, la interfaz y la persistencia automática. El adaptador puede fallar al escribir después de emitir `done`; falta definir esa comunicación. También faltan autorización, política de privacidad y retención y medida del coste completo. Filtrar por conversación no autentica. Véase el [diseño del historial](../design/persistencia-historial-feedback.md).

## Verificación de entrega

Validación completa en macOS ARM64, con dependencias locales desde los lockfiles y Node 24.22.2 y Python 3.12.16 fijados por mise. `mise run check` pasa: 369 pruebas del servicio, 35 live omitidas, 26 de scripts, lint, tipos, contrato regenerado sin deriva y build. El check detectó un separador ausente entre imports de una prueba; se corrigió y se repitió el check completo.

Tres pasadas Playwright con axe pasan con 183 pruebas aprobadas y cuatro live omitidas cada una. El humo HTTP atravesó el proxy web, la API y los modelos reales: documento con cita, factura, aclaración y rechazo correctos; `x-request-id` coincide con `done.request_id`. Se usaron datos sintéticos y puertos aislados. OCR respondió al health check; este humo no vuelve a probar la ingesta OCR. Todos los procesos propios se cerraron por PID.

Hay 692 enlaces internos comprobados, 0 rotos, y ninguna coincidencia del nombre privado. La auditoría de publicación se ejecuta sobre el commit final en un clon limpio con todas las tags semver; su resultado y SHA quedan en el registro privado de integración. La interfaz no cambia visualmente y no hay capturas nuevas. Las mediciones históricas de [latencia](../modelos-hardware.md#latencia-de-una-carga-sintética-local) son sintéticas, tienen diez muestras por operación y no prueban capacidad sostenida.
